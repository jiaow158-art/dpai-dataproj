## 一、核心结论（先记住这条）

```
毛利率分母 = notax_sales_net_amt（不含税销售净额）

❌ 不是 ambperformance（含税达成额）
❌ 不是 deal_price_total（成交总价）
❌ 不是 zhsxse（含税销售额）
```

据 FI329 实证，三套毛利率（实际A / 标A / 阿米巴）**分母全部是 `notax_sales_net_amt`**。

**当前知识库的错误写法**：

```sql
-- ❌ 错（含税分母）
SUM(amb_profit_amt) / NULLIF(SUM(ambperformance), 0) * 100

-- ✅ 对（不含税分母）
SUM(amb_profit_amt) / NULLIF(SUM(notax_sales_net_amt), 0) * 100
```

## 二、表 A｜基础指标映射（FI329 原样）

| 报表指标 | 物理字段 | SQL 表达式 | 单位 | 含税属性 |
|---|---|---|---|---|
| 业绩 | `ambperformance` | `SUM(ambperformance/10000)` | 万元 | **含税** |
| 不含税销售净额 | `notax_sales_net_amt` | `SUM(notax_sales_net_amt/10000)` | 万元 | **不含税** |
| 销售面积 | `zxsmj` | `SUM(zxsmj/10000)` | 万㎡ | — |
| 销售数量 | `zxssl` | `SUM(zxssl/10000)` | 万片 | — |
| s销售面积 | `s_zxsmj` | `SUM(s_zxsmj/10000)` | 万㎡ | 业绩口径 |
| s销售数量 | `s_zxssl` | `SUM(s_zxssl/10000)` | 万片 | 业绩口径 |
| 成交总价 | `deal_price_total` | `SUM(deal_price_total/10000)` | 万元 | 含税（比业绩多约 5%） |
| 分成后实际毛利额 | `gross_profit_after_sharing` | `SUM(gross_profit_after_sharing/10000)` | 万元 | — |
| **整体毛利**（实际成本毛利额） | **无物理字段，需现算** | `SUM(notax_sales_net_amt/10000) − SUM(actual_cost_exclude_logistics/10000)` | 万元 | 不含税 |
| 标A毛利额 | `a_overall_profit_amt` | `SUM(a_overall_profit_amt/10000)` | 万元 | 不含税 |
| 阿米巴毛利额 | `amb_profit_amt` | `SUM(amb_profit_amt/10000)` | 万元 | 不含税 |
| 实际A成本 | `act_cost_sum_amt` | `SUM(act_cost_sum_amt/10000)` | 万元 | — |
| 标A成本 | `standard_price_a` | `SUM(standard_price_a/10000)` | 万元 | — |
| 阿米巴成本 | `amb_internal_price` | `SUM(amb_internal_price/10000)` | 万元 | — |
| 返点 | `zfdje` | `SUM(zfdje/10000)` | 万元 | — |
| 使用积分 | `zsyjf` | **`0 − SUM(zsyjf/10000)`（带负号）** | 万元 | — |
| 预提积分 | `zytjf` | `SUM(zytjf/10000)` | 万元 | — |

### 三个必须注意的点

1. **`整体毛利` 在 `dm_fin_operations_mix_sum_t` 中不存在对应列**，必须现算 `notax_sales_net_amt − actual_cost_exclude_logistics`。
   **不要**用 `gross_profit_after_sharing` 替代 —— 那是另一个指标「分成后实际毛利额」。

2. **`整体毛利` 与 `实际A成本` 用的成本字段不同**（FI329 自身如此，请照抄，不要"修正"）：
   - 整体毛利 → `actual_cost_exclude_logistics`（剔除物流成本）
   - 实际A成本单价 → `act_cost_sum_amt`（含分摊）

3. **使用积分是负值**：`0 − zsyjf`。不要写成 `ABS(zsyjf)`。

## 三、表 B｜三套毛利率

| 毛利率 | 分子 | 分母 | 完整 SQL |
|---|---|---|---|
| **实际A毛利率** | 整体毛利<br>`notax − actual_cost_exclude_logistics` | `notax_sales_net_amt` | `(SUM(notax_sales_net_amt) − SUM(actual_cost_exclude_logistics)) / NULLIF(SUM(notax_sales_net_amt),0) * 100` |
| **标A毛利率** | `a_overall_profit_amt` | `notax_sales_net_amt` | `SUM(a_overall_profit_amt) / NULLIF(SUM(notax_sales_net_amt),0) * 100` |
| **阿米巴毛利率** | `amb_profit_amt` | `notax_sales_net_amt` | `SUM(amb_profit_amt) / NULLIF(SUM(notax_sales_net_amt),0) * 100` |

**FI329 中没有「分成后毛利率」这个指标** —— 它只有「分成后实际毛利额」，不计算率。
因此知识库中用 `gross_profit_after_sharing` 算毛利率属于自创口径，应废弃。

## 四、表 C｜八套单价（分母有两组，不要混用）

| 单价 | 分子 | 分母 | 字段组合 |
|---|---|---|---|
| 成交单价\_数量 | 成交总价 | **s销售数量** | `deal_price_total / s_zxssl` |
| 成交单价\_面积 | 成交总价 | **s销售面积** | `deal_price_total / s_zxsmj` |
| 实际A成本单价\_数量 | 实际A成本 | **销售数量** | `act_cost_sum_amt / zxssl` |
| 实际A成本单价\_面积 | 实际A成本 | **销售面积** | `act_cost_sum_amt / zxsmj` |
| 标A成本单价\_数量 | 标A成本 | **销售数量** | `standard_price_a / zxssl` |
| 标A成本单价\_面积 | 标A成本 | **销售面积** | `standard_price_a / zxsmj` |
| 阿米巴成本单价\_数量 | 阿米巴成本 | **销售数量** | `amb_internal_price / zxssl` |
| 阿米巴成本单价\_面积 | 阿米巴成本 | **销售面积** | `amb_internal_price / zxsmj` |

### 关键差异

| 场景 | 分母字段 | 原因 |
|---|---|---|
| 成交单价 | `s_zxssl` / `s_zxsmj` | 与成交总价同为"业绩口径" |
| 成本单价 | `zxssl` / `zxsmj` | 与成本同为"销售口径" |

**两组不能互换**，否则单价偏差显著。

### 单位换算

```
金额 ÷ 10000 = 万元
数量 ÷ 10000 = 万片
面积 ÷ 10000 = 万㎡
→ 万元 / 万片 = 元/片
→ 万元 / 万㎡ = 元/㎡
```

## 五、表 D｜硬约束

| 项 | FI329 原样 | 移植到 SQL 的建议 |
|---|---|---|
| 组织过滤 | `coalesce(node_name2,'#') NOT IN ('R91000002','R91000001')` | 保留（两者均为排除部门） |
| data_source | `IN ('${data_source}')`，**报表默认参数 = `'S','T'`** | 默认 `IN ('S','T')`；知识库现有 `IN ('S','T','D','')` 需业务确认 |
| 时间过滤 | `substr(calday,1,6) BETWEEN start AND end` **且** `calday <= to_char(now() - interval '1 day','yyyyMMdd')` | 后半句必须保留，否则会带入未来/当日未结数据 |
| 除法 | `datatool.division_by_zero(a,b)`（帆软内置函数） | 用 `NULLIF(b,0)` 等价实现 |
| 单位 | 所有金额/数量/面积 `/10000` | 输出万元；单价为元/片、元/㎡ |
| 组织层级 | `org1 ~ org9` | 对应 `node_name1~9` / `node_desc1~9` |
| 上层运营单位 | `orgup = LEFT(org1,9) + (RIGHT(org1,1) − 1)` | 用于"与上层运营单位对比"类偏差率 |

### 偏差率族（FI329 独有，知识库完全缺失）

FI329 对每个指标都算了 4 类对照：

```
本期实际值 / 同期值（同比，start-100）/ 环比值（-1 个月）/ 预算值（_ys 后缀）
上层运营单位同比偏差率 / 环比偏差率 / 预算偏差率
"指标与上层运营单位对比（同比偏差率）" = (实际值 − 同期值) − 上层运营单位同比偏差率
```

需要补进知识库，作为"偏差率/归因分析"类问题的标准口径。

## 八、证据与复核方法

`.cpt` 文件实际是 XML 明文（文件头 `<?xml version="1.0" encoding="UTF-8"?><WorkBook>`），可直接解析复核：

```powershell
$p = 'reportlets\PC端\集团财经平台\财经\毛利以上\FI329集团经营分析-对比分析.cpt'
$c = Get-Content -Raw -Encoding UTF8 $p

# 1) 报表引用了哪些表
[regex]::Matches($c,'(?i)\b(dm|dwr\w*|dwi\w*|sdi|upload)\.[a-z0-9_]+') |
  %{ $_.Value.ToLower() } | Sort-Object -Unique

# 2) 全部指标名
[regex]::Matches($c,"select '([^']+)' as showname") | %{ $_.Groups[1].Value }

# 3) 某指标的计算表达式（往前取 700 字符）
$m = [regex]::Match($c,'本期阿米巴毛利率实际值')
$c.Substring([Math]::Max(0,$m.Index-700), 720)
```

**引用原文（阿米巴毛利率）**：

```sql
datatool.division_by_zero(
  sum(case when substr(calday,1,6)>='${start_date}' and substr(calday,1,6)<='${end_date}'
            and calday<=to_char(now() - interval '1 day','yyyyMMdd')
           then 阿米巴毛利额 end),
  sum(case when substr(calday,1,6)>='${start_date}' and substr(calday,1,6)<='${end_date}'
            and calday<=to_char(now() - interval '1 day','yyyyMMdd')
           then 不含税销售净额 end)
) as 本期阿米巴毛利率实际值
```

**引用原文（指标别名映射）**：

```sql
sum(t.ambperformance/10000)            as 业绩,
sum(t.zxsmj/10000)                     as 销售面积,
sum(t.zxssl/10000)                     as 销售数量,
sum(t.s_zxsmj/10000)                   as s销售面积,
sum(t.s_zxssl/10000)                   as s销售数量,
sum(t.act_cost_sum_amt/10000)          as 实际A成本,
sum(t.standard_price_a/10000)          as 标A成本,
sum(t.amb_internal_price/10000)        as 阿米巴成本,
sum(t.notax_sales_net_amt/10000)       as 不含税销售净额,
sum(t.gross_profit_after_sharing/10000) as 分成后实际毛利额,
sum(notax_sales_net_amt/10000) - sum(actual_cost_exclude_logistics/10000) as 整体毛利,
sum(t.a_overall_profit_amt/10000)      as 标A毛利额,
sum(t.amb_profit_amt/10000)            as 阿米巴毛利额,
sum(t.zfdje/10000)                     as 返点,
0 - sum(t.zsyjf/10000)                 as 使用积分,
sum(t.zytjf/10000)                     as 预提积分,
sum(t.deal_price_total/10000)          as 成交总价
```
